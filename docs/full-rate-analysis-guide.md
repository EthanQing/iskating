# 12 路完整帧率分析用户指南

## 使用前准备

- FastAPI、PostgreSQL 和 Ubuntu DeepStream worker 已部署且 worker 正常领取任务。
- 12 路录像位于 Windows 与 Ubuntu 都可访问的同一 NAS 根目录。
- 每路录像具有可靠且不倒退的 PTS；已知各源开始时间，必要时准备人工毫秒校正值。
- Windows 能通过盘符或 UNC 路径访问 NAS，例如 `Z:\iskating` 或 `\\nas\iskating`。

## 准备清单

点击主窗口“完整分析”，可逐格填写，也可导入包含恰好 12 个源的 JSON：

```json
{
  "sources": [
    {
      "cameraId": 1,
      "sourceUri": "nas://videos/2026-07-14/camera01.mp4",
      "width": 1920,
      "height": 1080,
      "fps": 60,
      "durationMs": 3600000,
      "sourceStartedAt": "2026-07-14T09:00:00.000+08:00",
      "manualCorrectionMs": 0
    }
  ]
}
```

实际文件必须包含 `cameraId` 1 到 12 各一项。`sourceUri` 相对于统一 NAS 根目录；不要写 `Z:`、UNC 路径或 Ubuntu 绝对路径。`durationMs` 是毫秒，`sourceStartedAt` 使用带时区的 ISO 8601 时间。

## 创建和监控

1. 在“Windows NAS 根目录”填写 `nas://` 对应的盘符或 UNC 根目录。
2. 检查 12 路 URI、分辨率、FPS、时长、开始时间和校正值。
3. 点击创建批次。客户端会同时创建第一个不可覆盖的分析运行。
4. 任务面板每 2 秒刷新总进度和每路状态。允许吞吐低于 720 帧/秒；完整性优先。
5. 某一路失败时先查看错误。修复媒体、NAS 或 worker 后点击重试；已提交的其他机位结果不会丢失。
6. 取消只停止当前运行，不删除旧激活版本。模型或同步校正变化时创建新运行，不覆盖旧结果。

## 回放和版本切换

- 已完成的 10 秒区间可在任务仍运行时渐进回放。
- 随机 seek 到未完成或缺失区间时，界面会清空检测框并显示状态，不会沿用旧帧结果。
- 新运行只有在 12 路全部完成完整性校验后才能激活。激活后，训练记录和回放统一读取新版本，客户端结果缓存会被清空。
- 旧 session、旧单视频任务和旧姿态摘要仍按原路径读取。

## 清理注意事项

完整结果与原视频使用同一生命周期。删除视频前服务端会检查运行引用；视频资产全部确认清理后，相关结果分块会删除，运行与批次保留最小审计状态。请勿直接删除数据库分块索引或只删除 NAS 分块文件。
