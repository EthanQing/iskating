当前状态：本地桌面产品版已补齐“复盘校准闭环”：结构化训练记录、动作级回放、人工复核、手动新增动作、标准参考视频、动作标准编辑、人工优先趋势和 Markdown/CSV/PDF 报告。云同步、远程教练、队伍平台、权限和自动动作分类仍不在当前本地版范围。

## 背景

当前产品已经具备多路摄像头预览、主视图采集、人体姿态识别、骨架/轨迹展示、实时评分、训练历史和自动建议。

但如果最终目标是面向滑冰运动员的日常训练动作标准系统，目前还缺少“动作标准、运动员上下文、训练计划、动作级复盘、教练协作、长期数据资产”等产品对象。下面清单按优先级记录未做功能，后续实现时应保持小步提交，并同步更新相关模块/流程文档。

- [x] 已做 v1：训练上下文选择。采集页支持选择运动员、教练、场地、训练阶段、本次目标和动作标准。
- [x] 已做 v1：动作标准库。内置 8 条滑冰训练动作标准，包含名称、类别、等级、目的、阶段、关键点、阈值、权重、常见错误和纠正提示。
- [x] 已做 v1：动作标准版本管理。`training_sessions` 和 `action_repetitions` 会记录 `standard_version`。
- [x] 已做 v1：动作类别体系。内置基础滑行、蹬冰、压步、转体准备、跳跃准备、落冰控制、旋转姿态、步法。
- [x] 已做 v1：动作选择入口。开始训练前手动选择动作标准；自动识别留后续。
- [x] 已做 v1：训练任务/计划。保存时按运动员和日期生成/更新今日训练计划与动作任务，记录目标次数、目标分、组数、休息时间和状态。

- [x] 已做 v1：个体化基线。PostgreSQL 自动维护运动员-动作标准维度的历史均值；手动调整阈值留后续。

- [x] 已做 v1：训练后复盘页。历史页卡片展示本次训练动作列表、最好/最差动作、关键错误时间轴、视频引用、教练批注和报告导出入口。

- [x] 已做：训练报告。支持导出单次训练 Markdown、CSV 明细和 PDF 复盘报告，包含训练概览、动作完成度、AI 原始分、人工修正、教练批注和动作明细。

## P1：摄像头与场地配置

- [x] 已做 v1：多机位标定。系统设置为 12 路相机保存是否参与轨迹、用途、场地覆盖起止距离、横向偏移、安装高度、朝向、俯仰和备注；轨迹控件会按场地段把多路姿态结果拼成全场轨迹。当前是线性场地段映射，不是完整畸变/透视标定。
- [x] 已做 v1：视角质量检查。开始采集前会检查参与轨迹的相机是否配置 IP 和有效覆盖段；系统设置可记录每路相机的质量/兼容备注。自动判断完整入镜、光照和关键点可见性仍需真实画面质量模型。
- [x] 已做 v1：机位用途管理。系统设置可为每路相机记录用途，默认 12 路按“轨迹分段”覆盖连续场地段。
- [x] 已做 v1：目标摄像头兼容清单。系统设置支持按机位记录兼容备注，RTSP 公共参数和每路 IP 仍统一落在 QSettings；正式品牌/编码兼容矩阵需要现场硬件验证后维护。
- [x] 已做 v1：摄像头配置模板。系统设置支持导入/导出 JSON 模板，批量配置公共 RTSP 参数、预览/主码流路径、NVR 回放模板、12 路 IP 和场地标定；模板导入先显示摘要确认，保存后仍写入 QSettings 并兼容旧配置。

## 推荐实施顺序

1. 先做运动员档案、动作标准库、动作选择入口和训练记录字段扩展，建立产品数据骨架。
2. 再做动作级计数、动作阶段拆分、动作级评分和实时纠错，让评分从通用姿态分变成训练动作分。
3. 接着做训练后复盘、视频片段、关键帧、报告和趋势分析，让运动员能看懂如何进步。
4. 然后补教练批注、人工标记、标准编辑和校准数据集，让系统能被教练持续修正。
5. 最后推进权限、安全、云同步、团队管理、部署发布和自动化测试。
