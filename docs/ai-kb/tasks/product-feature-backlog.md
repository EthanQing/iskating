## 背景

当前产品已经具备多路摄像头预览、主视图采集、人体姿态识别、骨架/轨迹展示、实时评分、训练历史和自动建议。

但如果最终目标是面向滑冰运动员的日常训练动作标准系统，目前还缺少“动作标准、运动员上下文、训练计划、动作级复盘、教练协作、长期数据资产”等产品对象。下面清单按优先级记录未做功能，后续实现时应保持小步提交，并同步更新相关模块/流程文档。

## P0：训练动作标准闭环

- [x] 已做 v1：运动员档案。SQLite 支持运动员姓名/编号、年龄组、身高体重、项目类型、技术等级、惯用方向/起跳脚、伤病限制和训练目标；当前 UI 支持新增姓名，其余字段使用默认值，完整编辑留后续。
- [x] 已做 v1：教练/运动员基础关系。SQLite 支持教练、运动员和关系表；训练记录可归属运动员和教练。
- [x] 已做 v1：训练上下文选择。采集页支持选择运动员、教练、场地、训练阶段、本次目标和动作标准。
- [x] 已做 v1：动作标准库。内置 8 条滑冰训练动作标准，包含名称、类别、等级、目的、阶段、关键点、阈值、权重、常见错误和纠正提示。
- [x] 已做 v1：动作标准版本管理。`training_sessions` 和 `action_repetitions` 会记录 `standard_version`。
- [x] 已做 v1：动作类别体系。内置基础滑行、蹬冰、压步、转体准备、跳跃准备、落冰控制、旋转姿态、步法。
- [x] 已做 v1：动作选择入口。开始训练前手动选择动作标准；自动识别留后续。
- [x] 已做 v1：训练任务/计划。保存时按运动员和日期生成/更新今日训练计划与动作任务，记录目标次数、目标分、组数、休息时间和状态。
- [x] 已做 v1：动作阶段拆分。动作标准记录关键阶段文本；尚未做逐阶段独立评分。
- [x] 已做 v1：动作级计数。`ActionRepetitionTracker` 按动作标准阈值、防抖和有效动作判定输出动作实例。
- [x] 已做 v1：动作级评分。`ActionStandardScorer` 按不同动作的权重和最低分重算动作分。
- [x] 已做 v1：动作错误识别。低分会映射为动作标准错误项或分项错误项。
- [x] 已做 v1：实时纠错提示升级。实时反馈包含问题、原因和建议动作。
- [x] 已做 v1：训练目标达成提示。训练过程中显示有效动作数、目标次数、均分、目标分和最好分。
- [x] 已做 v1：个体化基线。SQLite 自动维护运动员-动作标准维度的历史均值；手动调整阈值留后续。

## P0：训练记录与复盘

- [ ] 未做：结构化训练记录扩展。训练记录应至少增加 athleteId、coachId、planId、taskId、actionId、standardVersion、场地、训练阶段、目标、动作明细、视频引用、备注和教练批注。
- [ ] 未做：单次动作明细保存。需要保存每个动作实例的开始/结束时间、动作类型、有效性、总分、分项分、错误项和关键帧。
- [ ] 未做：视频片段引用。训练记录应能关联原始视频或关键片段，支持后续回看、对比和导出报告。
- [ ] 未做：视频回放播放器。需要支持慢放、逐帧、关键帧跳转、姿态叠加开关和错误片段快速定位。
- [ ] 未做：训练后复盘页。需要展示本次训练的动作列表、最好/最差动作、关键错误、时间轴和改进建议。
- [ ] 未做：关键帧/错误点时间轴。应能定位每次错误发生的时间点，并展示当时姿态、分数和纠错说明。
- [ ] 未做：标准动作对比。需要支持与标准动作视频、标准骨架或优秀样本进行对比。
- [ ] 未做：最好/最差动作对比。需要自动选出本次训练中代表性动作，便于运动员和教练复盘。
- [ ] 未做：训练报告。需要生成单次训练报告，包含训练概览、动作完成度、分项趋势、重点错误、下次训练建议和教练备注。
- [ ] 未做：历史趋势分析。当前历史页只做基础汇总，后续需要周/月趋势、动作掌握度、弱项雷达图、分项曲线和阶段性目标追踪。
- [ ] 未做：训练数据导出。需要支持 PDF 报告、CSV/Excel 明细或其他便于教练留档的导出形式。

## P1：教练协作与人工校准

- [ ] 未做：训练备注。运动员或教练应能记录主观感受、疲劳程度、冰面情况和训练重点。
- [ ] 未做：评分人工修正。需要允许教练对 AI 评分或错误项做人工修正，并保留修正来源。
- [ ] 未做：模型效果校准数据集。应沉淀教练修正后的样本，后续用于评估和优化评分规则或模型。
- [ ] 未做：动作标准编辑入口。教练或管理员应能维护动作标准、阈值、权重和提示文案；第一阶段可以是本地配置，后续再做管理界面。

## P1：数据、权限与安全

- [ ] 未做：长期数据存储方案。当前训练历史使用 QSettings，不适合多人、多年、可查询训练数据；需要评估 SQLite、本地文件库或服务端存储。
- [ ] 未做：数据迁移机制。训练记录字段扩展后需要兼容旧数据，并定义 schema/version 迁移策略。
- [ ] 未做：角色与权限。需要区分运动员、教练、管理员，控制谁能查看、编辑、导出和删除训练数据。
- [ ] 未做：隐私与授权。需要明确运动员视频、姿态数据、训练报告的本地保存、导出授权和删除机制。
- [ ] 未做：RTSP 密码安全。当前摄像头密码保存在本机设置中，后续需要加密或使用更安全的凭据存储。

## P1：AI 与识别能力

- [ ] 未做：模型精度选项真实生效。当前 fast/balanced/high 主要是 UI 和记录字段，需要确认并接入实际推理配置。
- [ ] 未做：手部姿态接入策略。仓库存在手部模型后端，但尚未接入主流程；需要决定是否用于滑冰动作分析，以及如何和人体姿态合并。
- [ ] 未做：冰刀/脚部细节识别。滑冰动作强依赖冰刀、刃向、脚踝和落冰状态，现有 Body17 关键点不足以覆盖这些细节。
- [ ] 未做：装备/场地辅助识别。后续可评估识别冰刀、标志线、场地边界和参考物，以提升动作评价可信度。
- [ ] 未做：动作识别模型或规则引擎。需要决定首阶段采用规则识别、模板匹配，还是训练专门动作分类模型。
- [ ] 未做：评分规则验证集。需要用真实滑冰训练视频验证动作标准、阈值和权重，避免评分只停留在视觉启发式。

## 推荐实施顺序

1. 先做运动员档案、动作标准库、动作选择入口和训练记录字段扩展，建立产品数据骨架。
2. 再做动作级计数、动作阶段拆分、动作级评分和实时纠错，让评分从通用姿态分变成训练动作分。
3. 接着做训练后复盘、视频片段、关键帧、报告和趋势分析，让运动员能看懂如何进步。
4. 然后补教练批注、人工标记、标准编辑和校准数据集，让系统能被教练持续修正。
5. 最后推进权限、安全、云同步、团队管理、部署发布和自动化测试。
