# 未确认问题

[返回索引](00-index.md) · [已知风险](05-pitfalls.md)

这里只记录无法仅靠当前仓库关闭、且会影响实现或上线的事项。已确认事实应移到模块、流程或 Reference；已解决项直接删除并在 Git 中追溯。

## 产品与权限

1. 正式用户角色、权限矩阵和审计要求是什么？
2. 客户端是否需要可见登录/退出、token 过期处理和账号管理？
3. 当前 `users.role` 与未使用的 `require_admin()` 应如何扩展为业务路由 RBAC？
4. 当前 person/ReID/轨迹能力的正式验收指标是什么，旧动作评分功能是否仍属于产品目标？

## 数据正确性

1. Participant UUID 应由客户端还是服务端作为唯一权威生成方？需要先修复轨迹/速度漏存并加真实 PostgreSQL 集成测试。
2. 完整分析上线时，“完整”的精确定义是否必须包含 frameIndex 全局连续、PTS 跨块单调、内容/元数据一致和零未声明缺口？
3. 是否需要 Alembic 或其他正式迁移机制替代开发期 reset + backfill 脚本？
4. QSettings 中 RTSP 和 API 凭据是否需要 Windows Credential Manager 或其他加密存储？

## 分析与模型

1. 是否需要为 run 冻结不可变模型、预处理和 gallery 快照，以支持可复现分析？
2. 是否会恢复姿态/关节/动作计数/技术评分？如恢复，需要新的版本化数据契约，不能直接复用已移除的客户端旧类型。
3. 是否需要自动跨机位全局 tracking，还是 athleteId 关联已经满足产品需求？
4. 目标 Windows 与 Ubuntu GPU、驱动、吞吐和 12 路 1080p60 压测基线是什么？

## 视频与部署

1. 目标摄像头/NVR 品牌、编码、RTSP 路径和回放模板是否固定？
2. Windows 客户端是否必须提供软件解码 fallback？
3. 是否计划实现真实 RTSP 录像、分段和校验，从而让 `planned` 视频资产变为 `recorded`？
4. 是否有仓库外 CI/CD、安装器、监控、日志采集和生产发布流程？
5. Qt 固定路径是否应改为可配置，以及正式支持的 Python/PostgreSQL 最低版本是什么？

## 任务恢复

1. 应持久化哪些 job 输入才能让应用重启后真正继续单视频/完整分析任务？
2. 完整分析暂停应只是停止 UI 轮询，还是应增加远端 worker 暂停协议？
3. 所有进度是否统一为 0–100，还是统一为 0–1？
