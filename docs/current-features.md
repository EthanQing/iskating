# 当前已完成功能概览

本文仅作快速摘要；143 个编号项的逐项盘点和已知边界见 [全量功能盘点与客户端流程重构](feature-inventory.md)。

## 1. 视频采集

- 支持最多 12 路 RTSP 预览和主视图播放。
- 支持离线视频导入、文件校验、训练 session 保存和历史回看。
- 支持导入恰好 12 路 NAS 同步录像批次，配置机位、分辨率、帧率、时长、开始时间和人工毫秒校正。
- 支持 RTSP 重连、UDP/TCP fallback、NVR 回放引用和视频资产索引。

## 2. 运动员检测与身份识别

实时主流程使用 `YOLO26x → PersonViT/MSMT17 ReID`：

- YOLO26x 只检测 COCO `person`，输出检测框和置信度。
- PersonViT 为检测框生成 768 维归一化 embedding。
- 当前 session 最多四名参与者进入 gallery，按余弦相似度匹配 athleteId。
- 候选接近时标记 `ambiguous`；无匹配时保留 `unknown`。
- 每个机位独立维护 trackId，机位之间可通过 athleteId 识别为同一运动员。
- 支持当前机位 track 的人工身份绑定，作为低置信度和未知身份兜底。
- 主视频覆盖层绘制检测框、身份标签和 trackId。
- 已识别的运动员在机位完成有效四点标定后，可将 bbox 底边中点投影为场地米制二维轨迹，并计算瞬时和 1000ms 平滑速度。
- 未标定机位、unknown 身份和无效映射不会生成伪造场地点。

## 3. 完整帧率离线分析

- Ubuntu 24.04 + DeepStream 9 worker 使用硬件解码、动态 batch YOLO26x、NvDCF 与固定 reinfer interval 的 PersonViT SGIE；YOLO `interval=0`，不足时背压而不主动丢帧。
- 每路按 10 秒生成 gzip JSONL 分块，临时写入、SHA256 校验、原子重命名后再登记索引；已提交分块可用于输出幂等检查，但失败重试仍会从源头重新解码和推理，再跳过重复写入。当前还会检查块内范围、分块不重叠和已登记帧总数。
- 支持批次、运行版本、每路进度、取消、重试、失败原因、已完成区间查询和完成版本原子激活。
- 回放按当前 PTS 预取完整结果并叠加 bbox、trackId 与身份；未完成或缺失区间清空覆盖层并显示状态。
- 新版本完成前继续使用旧激活版本；完整结果随视频生命周期清理，数据库保留最小审计记录。
- 当前未强制校验全局 frameIndex 从 0 到末帧无 gap、PTS 跨块单调，也未把 JSONL 内容与登记元数据逐项核对。
- 运行的模型/gallery 版本字段只是标签；worker 使用固定配置并在运行时读取当前 gallery，没有冻结可复现快照。完成或激活也不会自动创建训练 session。

## 4. 样本库

- 人员管理页支持 ReID 样本图片添加、查看和删除。
- 上传样本时生成 PersonViT embedding，并保存模型版本、预处理版本和维度。
- 只加载与当前模型版本和预处理版本一致的 embedding；模型升级后旧向量自动失效，需要重新生成。

## 5. 训练记录与历史兼容

- 新训练保存视频、参与者、检测框、机位、trackId、身份状态和身份置信度；满足身份与标定条件时还生成二维轨迹和速度。
- 新训练不生成姿态关键点、3D 骨架、动作评分、动作 repetition 或虚假的基线结果。
- 旧 `participant_pose_frames`、动作、评分和姿态复盘读取路径保留，便于历史记录兼容。
- FastAPI/PostgreSQL 继续保留旧字段，历史数据可继续查询和导出。
- 完整离线运行激活后由服务端按约 200 ms 派生 bbox/track/身份兼容摘要，不是新的姿态结果，也不把全量逐帧数据写入 PostgreSQL。
- 已知缺口：服务端会为主运动员重新生成 participant UUID，与客户端轨迹/速度引用的预生成 UUID 可能不一致，导致主运动员指标静默漏存。

## 6. 明确不提供的能力

当前版本不提供实时姿态关键点、3D 姿态、骨架刷新、跨机位全局 track/轨迹拼接、姿态评分、动作纠错和自动动作计数。动作标准和旧姿态/动作复盘界面主要用于历史数据兼容。

首期离线分析不提供自动视觉对齐、跨机位共享 trackId 或原始 embedding 长期存储；完整性优先，处理速度允许慢于录像时长。

## 7. 任务中心边界

- 单视频探测和 12 路完整分析共用单并发客户端任务列表。
- 暂停/继续只能保证当前进程内的 job；完整分析的暂停只停止客户端轮询，远端 worker 仍会运行。
- 应用重启后可显示遗留的 `paused` 任务，但当前不会重建 job 参数，不能直接继续。
- 完整运行进度返回 0–1 比例，任务中心按百分比直接展示，当前存在量纲不一致。

完整操作流程和 manifest 示例见 [12 路完整帧率分析用户指南](full-rate-analysis-guide.md)；重编后的九区客户端流程示意见 [HTML 原型](client-flow-prototype.html)。
