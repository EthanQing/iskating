# Windows 桌面端功能与使用流程蓝图

更新时间：2026-07-20。本文只讨论 Windows 桌面软件的用户可见功能、页面职责与操作流程，供重新设计导航、页面和交互使用。后端、数据库和 Ubuntu worker 只在它们影响用户操作时提及。

## 1. 用户在软件中要完成的事

| 用户目标 | 当前软件已有能力 | 建议归属 |
|---|---|---|
| 使用摄像头进行现场训练 | 多机位预览、开始/暂停/停止、实时检测、保存 session | 实时训练 |
| 使用一段本地录像进行复盘或分析 | 选择本地视频、播放、定位、低帧率本机检测、保存为导入视频记录 | 视频工作台 |
| 进行 12 路录像的完整分析 | 创建完整分析批次、查看进度、回放已完成区间 | 完整分析 |
| 维护运动员与身份样本 | 人员档案、样本照片、ReID 向量、人工绑定 | 人员与身份 |
| 制定训练内容 | 动作标准、训练人员、比赛/场次上下文 | 训练准备 |
| 查找和复盘过去训练 | 历史筛选、回看、校准、批注、片段定位 | 历史与复盘 |
| 了解训练结果 | 趋势、轨迹、速度、报告、导出、建议 | 结果与报告 |
| 配置运行环境 | 摄像头、视频路径、AI 策略、存储、连通测试 | 系统设置 |

## 2. 建议的一级导航

当前界面把大量功能塞进“运动员检测”页。重新设计时建议拆成以下一级区域：

1. **首页 / 今日训练**：入口、近期任务、最近记录、系统就绪状态。
2. **实时训练**：RTSP 摄像头现场训练专用。
3. **视频工作台**：单个本地视频的导入、播放、分析和保存专用。
4. **完整分析**：12 路录像的完整帧率分析专用。
5. **任务中心**：导入和完整分析任务的统一队列、进度、错误与恢复。
6. **历史与复盘**：历史检索、回看、人工校准、轨迹和姿态时间线。
7. **报告与建议**：报告中心、导出、趋势、个人基线和建议。
8. **人员与训练资料**：运动员、教练、身份样本、动作标准、比赛资料。
9. **系统设置**：摄像头、AI、存储、网络/NAS、连通测试。

## 3. 页面详细定义

### 3.1 首页 / 今日训练

**目的**：让用户知道系统是否可以开始工作，并快速进入最常见任务。

应展示：

- 后端连接、模型就绪、存储空间、摄像头可用数的简洁状态。
- 快捷入口：开始实时训练、分析本地视频、创建完整分析、查看任务、查看最近训练。
- 最近 session、进行中/失败任务、近期趋势摘要。

当前已有的状态信息：系统状态、AI 模型状态、数据库状态、训练状态、日期时间。

### 3.2 实时训练

**目的**：面向冰场现场，持续看 RTSP 画面并保存训练过程。

页面应包含：

- 主视频和 1–12 路机位缩略图；双击缩略图切主视频。
- 训练上下文：运动员、教练、动作标准、比赛、场次、参赛关系、参与者。
- 开始训练、暂停、停止、保存记录。
- 实时检测框、track、身份标签、AI 状态；已标定时显示二维轨迹/速度。
- 当前时长、当前机位、视频状态与断流提示。

已有流程：选择训练上下文 → 选择机位/确认摄像头 → 开始采集 → 实时检测 → 暂停/停止 → 保存记录。

不应放在本页的内容：导入本地视频、完整分析、人员管理细节、历史筛选、报告中心。

### 3.3 视频工作台（单视频）

**目的**：用户拿到一段视频后，明确完成“导入、查看、分析、标记、保存”的任务。

当前已有能力：

- 选择本地 mp4、mov、avi、mkv、m4v、wmv、flv、webm。
- 导入前自动检查文件、视频轨、时长、seek、D3D11VA 与首帧。
- 播放、暂停、停止、seek、变速、逐帧。
- 将视频登记为“导入视频”任务并在保存时关联训练记录。
- 在当前实现中，可在播放流可用时交由 Windows 本机 YOLO/ReID 低帧率分析。

建议流程：

1. **选择视频**：拖放或文件选择；显示文件名、时长、分辨率、编码和检查结果。
2. **设置分析**：选择运动员/动作标准；选择“仅播放复盘”或“本机实时分析”。
3. **执行分析**：独立的“开始本机分析 / 暂停 / 停止”按钮与进度/状态，不使用“开始采集”。
4. **查看结果**：视频上显示检测框、未识别/已识别标签和时间轴标记。
5. **保存结果**：保存为训练记录，或只保留视频任务供之后继续处理。

重要边界：当前并没有 Windows 单视频后台逐帧完整分析能力；它不能伪装成“完整分析”。

### 3.4 完整分析（12 路）

**目的**：将 12 路同步录像提交给 Ubuntu 分析主机做完整帧率处理。

用户可见功能：

- 导入 12 路 manifest / NAS 视频源。
- 查看每路媒体信息与时间校正。
- 创建分析运行、查看每路进度、吞吐、预计剩余时间、错误。
- 取消、重试、激活已完成版本。
- 在历史回放中使用已经完成的结果区间；缺口要明确显示。

此页应明确标注“完整分析需要远端分析主机”，不要与本机视频工作台混用。

### 3.5 任务中心

**目的**：集中展示所有耗时任务，避免用户不知道导入或分析是否在运行。

已有任务类型：

- 单视频导入。
- 12 路完整分析批次。

每项任务应展示：名称/来源、类型、创建时间、状态、百分比、错误、关联训练记录、暂停/继续/取消/重试入口。

### 3.6 历史与复盘

**目的**：查找一次训练，回看证据并进行人工修正。

已有检索条件：

- 运动员、教练、比赛、场次、动作标准、来源（训练/比赛/导入视频）。
- 保存时间、分数范围、关键词、有效性、复核状态、动作来源、片段时间。
- 保存时间、平均分、最佳分、有效动作数、时长排序及分页。

每条训练记录已有操作：

- 回看视频。
- 复盘校准。
- 姿态轨迹/时间线。
- 教练批注。
- 导出报告。

复盘校准已有能力：新增人工动作、修改动作时间、有效性、分数、错误项、反馈和教练备注；统计按人工优先计算。

### 3.7 报告与建议

**目的**：将训练记录转化为教练可使用的结论和可交付文件。

已有能力：

- 单次训练导出 Markdown、CSV、PDF。
- 报告中心按日期、参与者、训练内时间段和指标导出 CSV/PDF。
- 指标覆盖轨迹、速度、关节角、角速度；没有数据时需提示。
- 趋势、个人基线、训练建议展示。

建议将“导出”保留在具体 session 内，同时提供独立报告中心做批量筛选和导出。

### 3.8 人员与训练资料

应分为四个子页：

- **运动员**：姓名、编号、年龄组、身高体重、专项、水平、伤病和目标；新增、编辑、归档。
- **教练**：档案和带训运动员关系。
- **身份样本**：为运动员添加/删除照片样本，生成 ReID 向量，查看样本状态。
- **动作与比赛**：动作标准、参考视频、阈值/目标；比赛、场次、参赛关系、号码和道次。

当前“人员管理”“人工绑定”“比赛管理”“编辑标准”混在训练上下文中，建议移出实时训练页。

### 3.9 系统设置

已有配置项：

- 12 路摄像头、默认账号、端口、RTSP 路径、预览/主码流、NVR 回放模板。
- 四点冰面标定、每路轨迹开关。
- 分析精度档位、采集 FPS、分析目标 FPS、最大分析路数和自动降级。
- 本机视频资产目录、容量阈值、保留天数、清理候选。
- 摄像头配置 JSON 导入/导出、NAS 根映射、摄像头连通测试。

## 4. 当前可复用的操作流程

### A. 现场实时训练

`选择运动员与动作 → 选择机位 → 开始训练 → 观察框/身份/轨迹 → 暂停或停止 → 保存记录 → 历史复盘/报告`

### B. 单本地视频工作流

`选择视频 → 文件检查 → 选择人员和动作 → 播放或开始本机分析 → 查看检测状态/时间线 → 保存为导入视频记录 → 历史复盘/导出`

### C. 12 路完整分析

`导入 manifest → 校验 12 路和时间轴 → 创建运行 → 任务中心看进度/错误 → 完成后激活版本 → 历史回放与报告`

### D. 人员身份准备

`新建运动员 → 添加样本图片 → 生成 ReID 向量 → 在实时/视频页面查看自动身份 → 必要时人工绑定`

### E. 复盘修正

`历史检索 → 打开训练 → 回看视频/定位片段 → 人工修正动作 → 写批注 → 导出报告`

## 5. 重新设计时必须保留的事实

- 本机实时能力是“人体框 + track + ReID + 轨迹/速度”，不是新关键点骨架或自动技术评分。
- 即使没有 ReID 样本，只要检测正常也应该有“未识别”人体框。
- 本地视频播放和本机 AI 分析依赖 D3D11VA；“能播放”不等于“能分析”。
- 12 路完整分析与 Windows 本机分析是两种产品能力，速度、结果粒度、环境和用户预期不同。
- 历史中可能存在旧姿态、旧评分和旧动作数据；新页面需清楚标注数据来源，不要把旧兼容能力误表示为新实时能力。
- 归档人员仍会保留在历史记录中；删除不能破坏历史。

## 6. 当前界面最需要解决的问题

1. “开始采集”同时被用户理解为摄像头训练和离线视频分析，必须拆分。
2. 导入视频后缺少“下一步做什么”的独立流程、状态和结果页面。
3. 完整分析、任务中心和视频导入的入口分散，用户无法建立任务模型。
4. 训练准备资料与实时训练操作混在一起，现场操作负担过重。
5. 历史、复盘、报告和建议分散但依赖同一批结果，应该建立统一结果中心。
6. AI 运行状态要在视频区域可见，而不能只停留在顶部状态栏。

## 7. 当前不存在的桌面端能力

- Windows 单视频后台逐帧完整分析。
- Windows DeepStream worker。
- 新实时关键点骨架、自动动作识别/计数、自动技术评分。
- 云同步、团队协作、桌面端角色权限界面。
- 自动录制、剪辑和复制训练视频。
- 通用软件解码 fallback。
